# 路由占位页面设计

## 目标

为 `apps/web` 搭建招新管理后台的基础页面路由。每个新页面暂时只展示页面名称和“待开发”提示，不接入业务数据或鉴权逻辑；现有首页健康检查保持不变。

## 页面与路由

| 路径 | 路由名 | 页面标题 |
| --- | --- | --- |
| `/` | `home` | 首页（现有页面） |
| `/login` | `login` | 登录 |
| `/dashboard` | `dashboard` | 控制台 |
| `/forms` | `forms` | 表单管理 |
| `/recruitment` | `recruitment` | 招聘管理 |
| `/templates` | `templates` | 邮件模板 |
| `/settings` | `settings` | 系统设置 |

## 方案与取舍

采用“路由集中声明 + 复用占位页面组件”的方案：

- 路由配置继续集中在 `apps/web/src/router/index.ts`，沿用当前 Vue Router 4 和 `createWebHistory`。
- 新增一个通用占位视图，通过路由 `meta.title` 或组件参数显示页面标题，避免为内容完全相同的页面复制多个 `.vue` 文件。
- 保留 `Home.vue` 的现有实现，因为它包含 API 健康检查，是当前前后端联通的脚手架验证入口。

相比每个页面单独创建空组件，这个方案改动更少、后续替换单页内容时仍可直接把对应路由换成真实视图。暂不引入布局、导航菜单、路由守卫或额外 UI 依赖，避免超出当前“占位页”范围。

## 组件与数据流

占位页组件从当前路由读取 `meta.title`，渲染统一的 Element Plus 卡片：

```text
URL -> Vue Router -> PlaceholderView -> route.meta.title
                                      -> “待开发”
```

页面只依赖 Vue Router 的当前路由和现有 Element Plus 全局注册，不请求 API、不修改后端、不保存状态。

## 错误处理与兼容性

- 不增加未定义路由的自定义错误页；保留 Vue Router 默认行为。
- 不改变 `/` 路由、首页健康检查调用或现有应用根结构。
- 使用中文页面标题，沿用项目当前中文界面文案。

## 验证

- 增加路由声明的自动化断言，覆盖所有目标路径、路由名和页面标题，防止新增页面漏注册或配置错误。
- 运行 `pnpm --filter @iot-pillot/web typecheck`。
- 运行 `pnpm --filter @iot-pillot/web build`。
- 通过开发服务器逐一访问目标路径，确认页面可渲染并显示对应标题和“待开发”。

## 不在本次范围

- 登录、表单、招聘、邮件模板、系统设置的真实功能。
- 后台布局、侧边栏、面包屑、权限守卫和接口请求。
- 后端路由或共享 DTO 变更。
