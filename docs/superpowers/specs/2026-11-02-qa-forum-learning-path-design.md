# 招新问答、内部论坛与学习路线

## Problem Statement

招新阶段新生的疑问散落在私聊与群里：同一个人问过的问题下一个人还要再问一遍，管理员重复回答同样的内容；已经答过的东西没有任何沉淀，招新一结束就归零。同时，新生拿到方向后不知道「先学什么、按什么顺序学」，管理员每次都要手打一份学习路径。

平台现在有招新流程、表单、邮件、工作室成员/项目/知识库，但**没有任何内容协作能力**：全仓没有论坛、提问、回复、附件、上传统计，`packages/shared-types` 也没有相关草案。工作室知识库（#196）只对 admin 开放、只有管理员维护、正文只是一个 `textarea`，既不能让用户提问，也不能承载图片。

需要补两块能力：

1. **提问**：登录用户能发帖提问、可以配图、能被回复；管理员能回答、能标记已解决。**工作室内部论坛与它大体逻辑相同**，用权限隔开。
2. **学习路线推荐**：管理员按方向维护阶段化的学习路径，用户按方向浏览并标记自己学到哪。

约束：报名与表单提交必须登录、权限统一走 `AuthModule` 中间件、schema 变更必须走迁移、SMTP 外发统一走 `MailModule`、模板渲染统一走 `TemplateModule`、依赖最小化、避免预留用不到的扩展点。

## Solution

一套**内容模型**（帖子 + 回复 + 附件）承载招新问答与内部论坛，用 `scope` 列区分、用**路由分组**隔离权限；一套**附件能力**（上传 / 绑定 / 代理读取 / 孤儿清理）承载图片，对象字节放在 S3 兼容对象存储；一套 **Markdown 渲染器**（token 流映射 VNode）被正文、预览与摘要三处共用。学习路线是**单表 + JSONB 阶段 + 服务端生成的稳定阶段 id**，用户进度单独一行。回复触发邮件通知但**不阻塞回复本身**。

外观上：用户在个人首页（`/user/*`）进入「问答」与「学习路线」；管理员在后台侧边栏「工作室」分组进「内部论坛」、在「工作台」分组进「学习路线管理」。两处内容区共用同一套列表 / 详情 / 编辑器组件，只在内容域与入口上有差别。

## User Stories

### 招新问答（登录用户）

1. 作为一个已登录的招新候选人，我想在问答区看到按时间倒序的提问列表，以便知道大家都在问什么。
2. 作为一个已登录用户，我想按招新方向筛选提问列表，以便只看与我方向相关的问题。
3. 作为一个已登录用户，我想用关键词搜索提问的标题与正文，以便找到已经有人问过的问题。
4. 作为一个已登录用户，我想翻页浏览提问列表，以便不被一次加载几十条拖慢。
5. 作为一个已登录用户，我想点开一条提问看到完整正文与全部回复，以便读到完整上下文。
6. 作为一个已登录用户，我想在发帖时选择方向，以便提问被同方向的人看到；如果我不选，系统使用我资料里的方向。
7. 作为一个已登录用户，我想在正文里插入图片，以便用截图说明问题。
8. 作为一个已登录用户，我想一次最多插入 9 张图片、每张不超过 10 MiB，以便知道边界在哪里。
9. 作为一个已登录用户，我想在图片上传中看到独立的进度状态与失败重试按钮，以便网络抖动时不用重写正文。
10. 作为一个已登录用户，我想在提交前预览 Markdown 的渲染效果，以便确认格式与图片位置正确。
11. 作为一个已登录用户，我想在发帖后继续编辑自己的帖子，以便修正笔误。
12. 作为一个已登录用户，我想删除自己的帖子，以便内容不合适时撤下。
13. 作为一个已登录用户，我想回复别人的帖子，以便参与讨论。
14. 作为一个已登录用户，我想在回复里也插入图片，以便用截图回答。
15. 作为一个已登录用户，我想把帖子标记为已解决，以便列表里能区分出已经有人回答了。
16. 作为一个已登录用户，我想筛选「只看未解决」的帖子，以便找到还能帮上忙的问题。
17. 作为一个已登录用户，我想在被回复时收到邮件通知（邮件里有帖子标题与回复摘录），以便不用反复刷页面。
18. 作为一个已登录用户，我不希望自己回复自己的帖子时也收到邮件，以便减少噪音。
19. 作为一个已登录用户，我想在列表项上看到「含图 N 张」标记，以便知道哪些问题配了图。
20. 作为一个已登录用户，我想在图片加载失败时看到「图片不可用」占位块，以便知道这里本该有张图。
21. 作为一个游客，我点问答入口时应该被引导去登录，而不是看到一个半残页面，以便体验一致。

### 内部论坛（管理员）

22. 作为一个管理员，我想在侧边栏「工作室」分组里找到「内部论坛」，以便进去发内部话题。
23. 作为一个管理员，我想在内部论坛发帖、回复、配图，操作方式与招新问答完全一致，以便不用学两套。
24. 作为一个管理员，我想确认内部论坛的帖子不会出现在招新问答的列表里，以便内部讨论不外泄。
25. 作为一个普通登录用户，我访问内部论坛的接口应该拿到 403、访问内部论坛的附件应该拿到 404，以便内部内容不被探测到存在。
26. 作为一个管理员，我想在招新问答里删除任何人的帖子，以便处理不当内容。
27. 作为一个管理员，我想发的回复在回复列表里置顶并标成「官方回答」，以便提问者一眼看到官方口径。
28. 作为一个管理员，我想在撤销管理员身份后我的历史回复自动不再算官方回答，以便身份只有一个真源。
29. 作为一个管理员，我想在招新问答里标记任何人的帖子为已解决，以便维持列表质量。
30. 作为一个管理员，我想将来把内部论坛开放给普通成员时只需要改路由分组，以便不用重写功能。

### 学习路线（管理员）

31. 作为一个管理员，我想在「工作台」分组里找到「学习路线管理」，以便进入管理页。
32. 作为一个管理员，我想在一页里同时编辑路线标题、正文、阶段列表与每个阶段的资源，以便整体把控。
33. 作为一个管理员，我想给阶段加标题与一句话说明，以便学习者知道这一步的目标。
34. 作为一个管理员，我想给每个阶段加多条资源（标题 + 链接），以便指向具体材料。
35. 作为一个管理员，我想用上下按钮调整阶段顺序，以便不依赖拖拽也能排序。
36. 作为一个管理员，我想在正文里插图，以便用架构图讲解路线。
37. 作为一个管理员，我想在资源链接不是 http/https/站内路径时被拒绝保存并看到具体是第几个阶段的第几个资源，以便直接改正。
38. 作为一个管理员，我想在别人同时编辑同一条路线时收到「已被其他人修改，请刷新后重试」，以便不静默覆盖他人的改动。
39. 作为一个管理员，我想删除路线时它只是被软删，以便用户的学习进度不变成悬空引用。
40. 作为一个管理员，我想每条路线最多 20 个阶段、每阶段最多 20 个资源，以便列表页不会被一行超大 JSONB 拖慢。

### 学习路线（登录用户）

41. 作为一个已登录用户，我想在个人首页找到「学习路线」入口，以便从这里进去。
42. 作为一个已登录用户，我想按方向筛选路线卡片列表，以便只看我这个方向的内容。
43. 作为一个已登录用户，我想在卡片上看到标题、方向名、阶段数与正文摘要，以便快速判断值不值得点开。
44. 作为一个已登录用户，我想在详情页看到阶段按顺序排列、每个阶段的说明与资源链接，以便照着学。
45. 作为一个已登录用户，我想把某个阶段标记为「我学到这」，以便下次回来知道自己到哪了。
46. 作为一个已登录用户，我想再点一次同一个阶段就取消标记，以便标错了能撤。
47. 作为一个已登录用户，我想在我还没标记过任何阶段时看到明确的空状态，以便知道这个功能是存在的。
48. 作为一个已登录用户，我想在管理员重排或删除阶段后我的进度仍指向原来那个阶段（阶段没了才回到未标记），以便进度不会静默指错。
49. 作为一个已登录用户，我想在某个方向还没有路线时看到「该方向暂无路线」，以便与「整站没有路线」区分开。
50. 作为一个已登录用户，我想在招新结束后仍能看到我方向的学习路线，以便内容不会因为方向关闭而消失。

### 图片与基础设施

51. 作为一个登录用户，我想上传图片时服务端按真实字节判断类型（只收 jpg/png/webp），以便改了扩展名的文件不会混进来。
52. 作为一个登录用户，我想每天最多上传 50 张图片，以便知道配额边界。
53. 作为一个登录用户，我想上传超过 10 MiB 的单张图片时拿到一条可读的 `{code, message}` 错误而不是 nginx 的空白 413 页面，以便知道是哪里超了。
54. 作为一个登录用户，我想图片长期缓存且不经过共享代理，以便滚动列表时不用重复下载。
55. 作为一个运维者，我想 `/health/ready` 在对象存储不可用时变红，以便部署回滚能自动发现存储故障。
56. 作为一个运维者，我想对象存储的数据挂在持久卷上，以便每次发布不会把图片全丢掉。
57. 作为一个运维者，我想对象存储在没有初始化步骤的情况下直接可用（应用启动自动建桶），以便全新环境一次拉起即可。
58. 作为一个不碰图片的开发者，我想默认的 `docker compose up` 不必拉起对象存储，以便本地开发不被额外依赖卡住。

## Implementation Decisions

### 模块与分层

沿用仓内既有范式（`domain` → `dto` → `repository` → `service` → `handler` → `wire` → `router`），后端新增 **3 个模块**：

| 模块 | 职责 |
| --- | --- |
| **Attachment** | 对象存储端口封装、上传落库、读取代理、配额、归属判定、正文绑定重算、孤儿清理 |
| **Content（Forum）** | 帖子与回复读写、已解决标记、软删、方向与关键词筛选、官方回答排序、回复通知入队 |
| **LearningPath** | 路线 CRUD、阶段 id 生成与对齐、资源校验、用户进度读写 |

Attachment 是**独立能力模块**而不是 Content 的子目录：它同时服务内容与学习路线两条业务线，且读取判定只依赖附件自身的绑定列。

前端新增 **3 个业务模块**（`qa`、`studio-forum`、`learning-paths`）+ **2 组共享组件**（`components/forum/` 的列表/详情/编辑器、`components/markdown/` 的渲染器与摘要函数）。`qa` 与 `studio-forum` 不互相 import，各自组装自己的页面与路由；**内容域作为参数**传给共享组件，HTTP 客户端只有一份。

### 数据模型

新增 **5 张表**，迁移从 `0016` 起同一批交付：

| 表 | 要点 |
| --- | --- |
| `content_attachments` | `CHECK (num_nonnulls(post_id, reply_id, roadmap_id) <= 1)`；只存 `object_key`，不存完整 URL |
| `forum_posts` | `scope IN ('recruitment','studio')`；标题 ≤ 120、正文 ≤ 20000；`resolved_at` 与软删列 |
| `forum_replies` | 无 `scope`、无标题；正文 ≤ 20000；软删列 |
| `learning_roadmaps` | `stages` 为 JSONB 数组；`CHECK (jsonb_typeof(stages)='array')`；`direction_code NOT NULL`；`version` 用于乐观锁 |
| `user_roadmap_progress` | `UNIQUE (user_id, roadmap_id)` |

**不建外键**：`author_id` / `uploader_id` / `direction_code` 都是软引用（用户可软删、方向属运营数据会新增与关闭），硬外键会让一次方向清理卡住历史内容。附件的三个目标列同样不建外键——内容行软删时附件保留。

索引：`forum_posts(scope, deleted_at, created_at DESC)`、`forum_posts(scope, direction_code)`、`forum_replies(post_id, created_at)`、`learning_roadmaps(direction_code, deleted_at, created_at DESC)`、`content_attachments(created_at)`（供孤儿清理扫描）。

**关键词检索**：`ILIKE` 扫主帖标题与正文，不建索引、不做全文检索、不搜回复正文；用户输入中的 `%` / `_` / `\` 需转义。

### 接口契约

统一响应 `{code, message, data}`；错误码沿用既有 `response.Code*`。**存在性一律用 404 表达**（不区分「不存在」与「无权看」），只有「已登录但无权调用该组接口」用 403。

**附件**

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/api/v1/attachments` | 登录 | 单次一张，multipart，流式收图；返回 `{id, url, content_type, size_bytes}` |
| `GET` | `/api/v1/attachments/:id` | 登录 | 代理转发字节流；归属判定在 service；响应 `Cache-Control: private, max-age=31536000, immutable` |

三层体积闸门：nginx `client_max_body_size 12m` > 应用层单请求 12 MiB > 单文件 10 MiB。配额：每人每 24 小时 50 次，复用既有固定窗口限流器（key 按用户 ID）。超限时**不写任何对象**。

**招新问答（`scope = recruitment`），全部挂在登录分组**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/v1/forum/posts` | 参数 `page` / `page_size` / `direction_code` / `keyword` / `resolved` |
| `POST` | `/api/v1/forum/posts` | 建帖 `{title, body, direction_code?}` |
| `GET` | `/api/v1/forum/posts/:id` | 帖子 + 回复（官方回答置顶，其余按时间正序） |
| `PUT` | `/api/v1/forum/posts/:id` | 作者或管理员；整体替换并重算附件绑定 |
| `DELETE` | `/api/v1/forum/posts/:id` | 作者或管理员；软删 |
| `POST` / `DELETE` | `/api/v1/forum/posts/:id/resolved` | 作者或管理员；置已解决 / 撤销 |
| `POST` | `/api/v1/forum/posts/:id/replies` | 回复 `{body}`；触发通知 |
| `PUT` | `/api/v1/forum/replies/:id` | 作者或管理员；**不**触发通知 |
| `DELETE` | `/api/v1/forum/replies/:id` | 作者或管理员；软删 |

**内部论坛（`scope = studio`）**：同一组 handler 路径挂在 `/api/v1/admin/studio/forum` 下，行为完全相同。handler 从路由分组绑定的上下文读内容域，**不解析 URL**。将来开放给普通成员，只需把这组路由从 admin 分组挪到登录分组。

**学习路线**

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/v1/learning-paths` | 登录 | 参数 `page` / `page_size` / `direction_code`；响应额外带 `directions: [{code, name, count}]` |
| `GET` | `/api/v1/learning-paths/:id` | 登录 | 含当前用户进度 |
| `PUT` | `/api/v1/learning-paths/:id/progress` | 登录 | `{stage_id}`，UPSERT |
| `DELETE` | `/api/v1/learning-paths/:id/progress` | 登录 | 清除 |
| `GET` / `POST` | `/api/v1/admin/learning-paths` | 管理员 | 列表 / 新建 |
| `GET` / `PUT` / `DELETE` | `/api/v1/admin/learning-paths/:id` | 管理员 | 详情 / 整体保存（`version` 必填）/ 软删 |

方向筛选项由路线接口**自带**，只含「有路线」的方向，不读招新方向的 `open` 开关——否则招新一结束路线页一个方向都不剩。

### 校验与边界

- 标题 ≤ 120 字符，正文与回复 ≤ 20000 字符；前端同步校验，**数据库 CHECK 是最终判定**。
- 阶段 ≤ 20，每阶段资源 ≤ 20；阶段 id 形如 `s_` + 8 位 base36，**服务端生成**，前端只当不透明字符串。保存时对齐：请求里有 id 且存在于旧数据 → 保留；无 id → 生成；旧数据有而请求没有 → 丢弃。
- 资源 url 与 Markdown 链接共用一份协议白名单：`http:` / `https:` / 站内 `/`。不合规**拒绝保存**并指明位置。
- 帖子方向取值优先级：显式选择 → 用户资料方向 → 最新一条报名记录的方向 → 留空。留空合法。
- 附件绑定唯一真源是**正文**：从 `body` 提取本站附件路径重算绑定集合；非法 id 让整次保存失败并返回精确错误，不静默忽略、不改写正文；外链图片不参与绑定。
- 谁能改：作者本人或管理员（service 判定）。官方回答**不落库**，由 service 现查管理员名单得出，只影响排序与展示。

### 交互

- **编辑器**：textarea + 预览双 Tab，预览与详情共用同一个渲染组件。图片一次一张、前端串行最多 9 次，成功后把 Markdown 语法插到光标处，textarea 下方显示缩略图条带（移除缩略图 = 从正文移除语法）；单张独立状态（上传中 / 失败可重试 / 可移除），提交时若有失败中的图则拦住。
- **渲染**：`markdown-it` 只做解析，token 流映射成 VNode，**全程不产生 HTML 字符串**（不走 `v-html`、不引 sanitizer）。`<img>` 统一带 `loading="lazy"` 与 `referrerpolicy="no-referrer"`；未知 token 降级为纯文本；正文标题整体降一级；代码块横向滚动不折行。
- **列表项**：标题 + 方向 + 作者 + 时间 + 回复数 + 「含图 N 张」+ 正文摘要（先剥标记再截断），不显示缩略图。
- **通知**：回复接口不等 SMTP。容量 256 的有界队列 + 单 worker；满则非阻塞丢弃并记 `[forum]` 日志。模板类型 `qa_reply`，未配置时用内置兜底文案照发。收件人只有帖子作者；自己回自己跳过；邮箱为空跳过；只发一次（编辑不重发）。
- **入口**：后台侧边栏「工作室」分组加「内部论坛」，「工作台」分组加「学习路线管理」（路径 `/recruitment/learning-paths`，不新建「招新」分组）；用户端在个人首页导航加「问答」与「学习路线」两项。两个用户页与两个管理页都是需要登录的路由。

### 部署

## Testing Decisions

接缝全部落在**仓内既有的那一层**，不新建抽象层：

| 层 | 接缝 | 为什么在这一层 |
| --- | --- | --- |
| Go handler | 内存桩实现 repository / service 接口 + 直接构造 gin 上下文 | 既有 `*_handle_test.go` 的最高接缝；一次覆盖鉴权、参数解析、错误映射、响应形状 |
| Go repository | 真实 SQL 对测试库 | 既有 `*_repo_test.go` 做法；孤儿清理条件、`ILIKE` 转义、唯一冲突只有 SQL 能暴露 |
| Go service | 依赖注入桩 | 既有 `*_usec_test.go` 做法；阶段 id 对齐、附件重算、官方回答判定都在这里 |
| Go router | 全 nil 依赖构造一次 | 既有 `router_test.go` 做法；gin 通配符与静态段冲突只在构造期暴露 |
| Web API 层 | `vi.spyOn(globalThis,'fetch')` 断言 URL 与 body | 既有 `src/api/*.test.ts` 做法 |
| Web 纯函数 | 直接调用 | 既有 `modules/*/model.test.ts` 做法 |

**唯一的例外**：对象存储需要一个**内存桩实现**（只做内存 map 的存储端口实现），否则上传链路的单测全部依赖真实容器。真实容器只出现在 compose 与 `smoke.sh`，不进单元测试。桩实现的就是存储端口本身，不加仓储层、不加 mock 框架。

**不做的**：不为 Markdown 渲染器做快照测试（token 到 VNode 的结构太脆），只测**安全性质**——`javascript:` / `data:` 链接降级为纯文本、`html` token 降级、`<img>` 两个属性齐全、未知 token 不丢内容。

必测行为（按风险排序）：

1. **权限**：普通用户打内部论坛路由 403；普通用户读内部论坛附件与软删帖子的附件都是 404；非作者改别人的帖子失败。
2. **绑定重算**：新建按正文绑定；编辑后消失的 id 解绑回孤儿；引用别人上传的 id 整次失败；外链图片不参与绑定。
3. **配额与闸门**：超过单文件 10 MiB 与超过单日 50 次都被拒，且超限请求不会写半截对象到 bucket。
4. **阶段 id**：重排后进度仍指向原阶段；删除中间阶段后新增不复用已删 id；请求里带未知 id 被丢弃而不是报错。
5. **乐观锁**：`version` 缺省报参数错误；版本不匹配返回可读冲突；不静默覆盖。
6. **通知**：SMTP 失败时回复仍成功；自己回自己不发；队列满丢弃不阻塞；编辑回复不发。
7. **筛选**：关键词里的 `%` / `_` 被转义；空方向帖子只在「全部」出现；路线方向筛选项不依赖招新方向开关。
8. **scope 隔离**：内部论坛的帖子不出现在招新问答列表，反之亦然。

验收命令：`go test ./...`（apps/api）、`pnpm --filter @iot-pillot/web test`、`pnpm -r typecheck`、`pnpm --filter @iot-pillot/web build`，以及 `deploy/smoke.sh`。
