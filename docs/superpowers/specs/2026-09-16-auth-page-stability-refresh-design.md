# 登录注册页稳定性与视觉更新设计

## 目标

优化 `apps/web/src/views/AuthView.vue`，解决桌面端在登录与注册之间切换时左侧品牌区域发生位移或尺寸变化的问题，并将页面表达调整为“以前后端为核心的 IoT 全栈工作室招新”。认证流程、字段、校验规则和接口行为保持不变。

## 问题根因

桌面布局只设置了 `min-height: 100dvh`。注册表单比登录表单高，内容可能撑高整个网格容器并触发页面级滚动条；可用视口宽度随之变化，百分比分栏重新计算，因此左侧品牌面板看起来发生抖动。切换内容本身不应改变外层双栏布局。

## 布局方案

- 桌面端将认证页固定在一个视口高度内，左右两栏共享稳定的网格轨道。
- 左侧品牌面板保持固定高度并隐藏自身溢出，不参与表单内容的高度计算。
- 右侧表单面板独立纵向滚动；内容较短时垂直居中，内容较长时保留安全的上下留白并允许完整滚动。
- 登录与注册只替换右侧字段区域，不重新挂载或移动左侧内容。
- 移动端继续使用单栏自然文档流，不固定页面高度，避免移动浏览器地址栏和软键盘造成可用性问题。

## 视觉与文案方向

保留现有“工程蓝图 / 研究手册”的识别度，但将主题从单一硬件节点改为全栈产品协作：

- 左侧主标题使用“从界面到服务，把想法做成真正可用的产品”。
- 描述明确工作室以前端与后端开发为核心，同时保留 IoT 项目的应用背景。
- 示意图改为前端界面、API 服务和数据层之间的连接关系，避免芯片、传感器等图形让工作室被误解为硬件实验室。
- 登录区强调“回到工作台继续协作”，注册区强调“提交资料，加入项目实践”。
- 保持深蓝、纸白和少量红色批注的单一视觉体系，不引入新依赖或外部图片。

## 动效与可访问性

- 切换反馈仅使用不影响布局计算的 `opacity` 和轻微 `transform`，不动画高度、宽度或定位属性。
- 遵循 `prefers-reduced-motion`，在减少动态效果时关闭新增切换动画。
- 保留现有标签、焦点样式、错误提示、ARIA 属性和键盘操作能力。

## 测试与验收

- 新增可自动验证的结构约束，确保桌面布局使用固定视口高度、右侧独立滚动，并在移动端恢复自然高度。
- 更新文案测试，验证页面包含“全栈工作室”、前端、后端和招新语义。
- 运行 AuthView 单测、前端完整测试、类型检查和生产构建。
- 在相同桌面视口下切换登录与注册，左侧面板的边界、标题、示意图和页脚位置不得变化；右侧注册内容可完整滚动。

## 非目标

- 不修改登录、注册 API 或数据结构。
- 不开放当前尚未实现的邮箱验证码功能。
- 不重构认证状态管理、路由或表单校验。
- 不新增字体、图标库或动画库。
