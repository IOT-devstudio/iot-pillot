# 登录注册页 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将现有 `/login` 占位页替换为可用的登录/注册单页，对接后端认证接口并实现“研究手册”视觉方向。

**Architecture:** 使用一个 `AuthView.vue` 承载登录与注册两种模式，使用独立的纯函数模块处理表单校验，使用 `api/auth.ts` 封装 `fetch` 请求，使用 `auth/session.ts` 管理 `localStorage` 会话。路由只把 `/login` 从占位组件切换到认证视图，其它页面保持不变。

**Tech Stack:** Vue 3 `<script setup>`、TypeScript、Vue Router 4、Element Plus、原生 `fetch`、Vitest。

## Global Constraints

- 认证页面入口固定为 `/login`，成功后跳转 `/dashboard`。
- 登录接口固定为 `POST /api/v1/login`，注册接口固定为 `POST /api/v1/register`。
- 验证码发送接口尚未注册；“获取验证码 · 暂未开放”按钮必须 disabled，不能发起请求。
- 会话对象保存于 `localStorage` 的 `iot-pillot.auth` 键。
- 视口宽度小于 `820px` 时隐藏左侧品牌区，右侧表单占满页面。
- 不新增依赖，不修改后端和 `packages/shared-types`。
- 所有新行为遵循 TDD：先写一个会失败的测试并运行确认失败，再写最小实现。
- TypeScript 严格模式保持通过；页面文案使用中文。

- [ ] **Step 3: Implement the minimal request module**

Create one private `postAuth<T>(path, payload)` helper using `fetch`, JSON headers and `JSON.stringify`. Parse the response body once; if `fetch` rejects or JSON parsing fails, throw `AuthRequestError` with “服务暂时不可用，请稍后重试”. Throw `AuthRequestError` when the HTTP status is not 2xx, `code !== 0`, or successful data is missing; preserve the backend `message` when available. Export `login` and `register` with the exact paths above.

```ts
async function postAuth<T>(path: string, payload: unknown): Promise<T> {
  const response = await fetch(path, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });
  const body = (await response.json()) as BackendResponse<T>;
  if (!response.ok || body.code !== 0 || body.data === undefined) {
    throw new AuthRequestError(
      body.message || "服务暂时不可用，请稍后重试",
      response.status,
      body.code,
    );
  }
  return body.data;
}
```
