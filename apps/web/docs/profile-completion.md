# 个人资料完善（Issue #101）

本票只实现前端行为，沿用已合并的 `/api/v1/me` 和本人招新申请接口。
不改 Go、数据库、角色权限或后端资料字段的三态更新语义。邮箱仍不可修改，报名与表单提交仍须登录。

## 使用规则

- 设置页默认只读。「更改」进入编辑；「重置」恢复服务端确认的数据并保留编辑态；「取消」恢复数据并退出编辑；保存成功回到只读，失败保留输入。
- 班级和学号必填，QQ 选填。班级去首尾空白且不超过 64 个 Unicode 码点；学号只接受完整十进制正整数，限制在 JavaScript 安全整数范围。负数、小数、指数写法和非数字均给字段错误，不再静默转 null。
- `/me` 以学号 0 表示未填，前端因此拒绝 0，避免「已保存」后仍需补全。后端允许非负整数的既有契约保持不变。
- 姓名继续支持 3–20 个 Unicode 码点或留空清除。邮箱只读，无用户名修改入口。
- 两个登录入口共用资料检查；每次登录（含注册成功后的自动登录）重新获取 `/me`。缺少任一必填字段就在受保护页面显示补全横幅，提供设置页链接；成功补全后自动消失。读取失败仅提示无法检查，不误判为资料缺失，也不把网络故障当登录失败。

## 方向依据

2026-10-15 用户确认采用**最新一条报名记录的方向**；无报名时保留资料方向。

- `GET /api/v1/recruitment/applications` 后端按 `id DESC` 返回，使用第一条 `direction_code`，不采用首页尚未提交的临时点选值，也不从多条申请中自行挑选有利于通过校验的值。
- 设置页方向为只读并自动展示最新报名方向。原资料方向为空时将其带入保存数据；原值非空且不一致时显示原值与冲突提示，禁止保存，提示联系管理员。
- 保存前再次读取最新报名记录，以发现其他标签页新报名。读取失败或未知方向时禁止提交；「重新核对方向」保留其他字段草稿。
- 不额外更改或删除报名记录。前端检查不能代替服务端约束，也不能保证读取与写入之间的原子一致性。
