# 本人姓名编辑（Issue #87）

前端依赖后端 #86，已合入提交 `b96efff`（PR #114）。仅通过登录后的
`GET /api/v1/me` / `PUT /api/v1/me` 维护令牌本人的资料。

- 设置页姓名可编辑，非空时为 3–20 个 Unicode 码点，保存前去掉首尾空白。
  留空发送 `name: null` 清除；资料请求不发送邮箱、用户名或目标用户 ID。
- 保存成功以返回的完整资料回填表单，并同步首页及菜单显示；保存失败保留编辑，
  显示错误，不把未保存的名字发布到其他页面。重置恢复最近确认的资料。
  已保存资料及会话清除会使较早的读取失效，避免旧请求覆盖新姓名或退出后的状态。
- 展示优先使用数据库返回的 `name`；明确清空后改用绑定邮箱或用户编号，
  避免回退到 JWT 中的旧 `username`。兼容旧接口未提供 `name` 时的用户名展示。
- 邮箱只读且不可修改。姓名修改不撤销当前会话，建议以绑定邮箱登录。
  不依赖刷新令牌更新名字，展示始终读取 `/me` 的最新 `name`。
- #101 已进一步调整班级/学号必填、只读/编辑切换、登录补全提醒和方向自动带出，
  以 [个人资料完善说明](profile-completion.md) 为准。学号转换仍兼容字符串和数字。

## 验证

开发代理的 `/api` 和 `/health` 统一指向 `http://113.44.193.72` 的 nginx
入口。服务器旧 :8080 实例对 `PUT /api/v1/me` 返回 404，不能作为本功能的
联调目标。Vite / Vitest 脚本显式指定 `vite.config.ts`，避免 TypeScript 构建
产出的旧 `vite.config.js` 优先加载而掩盖代理配置修改。

单元测试覆盖保存与重新加载、姓名清除、3–20 个 Unicode 码点、失败保留草稿、
重复提交及原有字段转换。`tests/profile-name.browser.cjs` 是 Playwright
`browser_run_code` 脚本，使用 :5174 的 Vite 页面及拦截的接口响应，在桌面
1440px 和移动端 320/375/390/430px 检查保存、刷新、重置、失败反馈、首页与菜单、
只读邮箱及横向溢出。接口响应是 fixture，不能视作生产数据库持久化验证。
