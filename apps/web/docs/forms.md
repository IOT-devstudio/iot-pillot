# 招新表单前端（Issue #93）

## 页面与入口

- `/forms`：管理员表单列表，服务端分页；开放/关闭及复制分享链接。
- `/forms/new`：选择真实招新轮次和方向，创建默认关闭的报名表。
- `/forms/:id/edit`：修改表单、调整题目顺序、试填草稿预览；手机切换编辑/预览。
- `/forms/:id/submissions`：分页查询真实提交，读取完整答案详情及关联申请编号。
- `/f/:shareToken`：登录用户填写。访客先去登录，登录后返回原地址；请求中发现会话失效也保留该地址。

管理端复用 `AdminLayout`、`PageHeader` 和全局暖纸/藏青色主题。填写页复用 Swiss Signal 外壳、蓝色与荧光黄标识。模块按路由懒加载。

## 接口与业务边界

`src/api/forms.ts` 对齐 BE-05 的 snake_case DTO，所有请求复用统一会话层。没有匿名读取或匿名提交请求，没有模拟数据入口。旧共享包的 camelCase 演示类型保持原样。

- 五种字段：短文本、邮箱、长文本、下拉选择、单项确认。
- 已确认 checkbox 采用单项确认：勾选为 `[题目标题]`，未勾选为 `[]`。不向服务端发送 checkbox options。
- 创建请求绑定 `round_id` / `direction_code`；创建后不可变，新建一律关闭。保存后可开放或分享；只有表单、轮次和方向均允许报名时，服务端才会接受提交。
- 字段数量、必填项、邮箱、下拉选项、字符长度等在前端校验，服务端仍是最终依据。
- 编辑保留既有字段 ID；只有字段发生变动时才 PATCH 完整字段列表。字段变动保存前重新查询提交数；若出现提交则停止保存并提示重新加载。
- 有提交时锁定全部字段定义，仍允许修改标题、说明和开放状态。历史未知字段 ID 的答案仍保留，标注为“已删除字段 #ID”。这属于前端保护，无法替代服务端并发约束或历史字段快照。
- 分享读取仅返回 `submitted` / `my_submission_id`，不返回本人历史答案；普通用户刷新后显示已提交确认。完整答案详情使用管理员接口，包含五类答案回显。
- 单次提交期间禁用重复操作；失败保留答案并允许手动重试，不自动重发 POST。服务端拒绝重复报名、关闭轮次/方向时，直接显示其错误说明。
- 提交请求仅包含 `values`；会话层核对加载资料时的账号 ID，阻止跨标签页切换账号后代交。邮箱字段仅作答案，不调用资料修改接口。
- 输入错误与题目关联，提交校验失败后聚焦首个错误字段，修正内容时更新错误提示；状态反馈供读屏器读取。
- 有未提交答案时离页或刷新提示确认，提交中阻止站内离页。更新个人资料在新标签打开，保留当前答案；草稿不写入浏览器持久存储。
- 复制剪贴板受限时提供可选中、手动复制的完整链接。

已知后端边界：创建申请与保存表单答案目前不在共同事务中，存答案失败可能遗留申请；前端只保留答案并反馈实际错误，不伪造成功或自动重试。

## 填写页视觉与交互（Issue #183）

`/f/:shareToken` 在 #93 的能力上重做版式与状态呈现，业务（读取、校验、提交、防重、账号切换保护）仍由 `useFormFilling` 承担，接口契约未改动。

页面顺序固定为：表单介绍（标题、可选说明、轮次与方向）→ 当前申请身份 → 表单问题 → 提交区域。状态优先级为 **加载 → 加载失败 → 成功/已提交 → 关闭 → 可填写**，成功与已提交排在关闭之前，已提交的用户不会看到「暂不接受提交」。

视觉基准是用户首页与 `signal.css`：纸色背景、深色文字、蓝色主操作、黄绿色只做局部强调（贴在「当前申请身份」小标签上，不再铺满整块底色）。正文、题目与输入统一 16px，辅助信息不小于 12px；输入框与主操作至少 44px 高；内容容器 `border-box`、最大宽度 800px 居中，桌面内边距 32px、小屏 20px；移动端提交按钮占满可用宽度，提交区随文档滚动。

填写与纠错：

- 校验仍在首次提交时集中触发，失败不发请求、保留全部答案；出现错误后沿用「修正即更新」的行为。
- 首个错误字段按**题目顺序**定位（`model.firstErrorFieldId`），不依赖错误对象的键枚举顺序；先滚动到可见再聚焦，减少动态效果时不做平滑滚动。
- 错误提示紧邻控件，通过 `aria-invalid` 与 `aria-describedby` 关联；邮箱题的「仅作本次申请答案」说明也挂进描述，读屏不会漏读。
- 单项确认的题目文字改用 `div` 承载：原先是 `<label>` 里再套一层 `<label>`，嵌套 label 属于非法结构。

成功态只回显接口返回的申请编号与提交时间，不硬编码「待审核」，也不新增申请状态映射；返回首页与查看申请都走 `/user/home`。

样式全部收在 `.swiss-signal .share-form-page` 下，管理端列表、编辑器、提交记录与共享的 `FormFields` 预览不受影响。前缀 `.swiss-signal` 是为了稳定压过 `signal.css` 的 `main`、`input`、`.form-error` 等通用规则，不依赖样式表加载顺序。

背景沿用用户首页与个人设置同一层 `.glass-backdrop`（`styles/liquid-glass.css`）：左上品牌蓝、右下黄绿的柔光晕，`position: fixed` + `pointer-events: none`，纯装饰不接事件。内容层用 `.share-form-page > :not(.glass-backdrop) { position: relative; z-index: 1 }` 压到光斑之上，否则文字会被光晕盖住。

验收截图（改动前后、校验失败、提交成功、管理端预览）只留在本地工作区 `outputs/issue-183/`，按仓库约定不入库；需要时用同一组模拟数据重跑即可复现。

`tests/forms.browser.cjs` 增加了 #183 的断言：首个错误按题目顺序（把 id 最大的题排到最前验证）、错误与控件的 `aria-describedby` 关联、16px 正文与 44px 控件高度、移动端主操作占满宽度、成功态不出现「待审核」。脚本用 CDP 拦截全部业务接口，不读写真实数据；截图为模拟请求下的结果，不作为真实联调通过的证据。
